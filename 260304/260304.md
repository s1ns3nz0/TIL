# 2. 헷갈렸던 부분
## 1) Application Layer와 Domain Layer의 Entity 제어 구조
![각 계층별 역할](https://tech.kakaopay.com/_astro/app_domain_entity_2.b3864ebe_1z8xYS.png)
### Domain 이외의 Layer
- Presentation: 요청, 응답 처리 담당으로 'HTTP를 어떻게 처리할 것인가'에 초점
- Application: 유즈케이스를 어떤 순서로 실행할 것인가로, '비즈니스 유즈케이스 마다 각 도메인을 어떤 순서대로 호출할 것인가'에 초점
- Biz-Component Layer: 카카오페이만의 계층으로, 공통되는 도메인을 조합해서 묶은 것
    + 모바일과 웹을 통해서 '즉시 납부'를 한다고 했을 때, '즉시 납부'를 하기 위한 도메인(잔액 차감, 납부 기록 생성)들을 묶어 둔 것
### Domain Layer
- Account: 잔액 차감은 normal 상태에서 금액이 0원 초과일 때만
- CreditLimit: 복원 시 이력 자동 기록, 과복원 불가
- Recovery: 납부 기록 생성 시 초기 상태는 Completd
> 즉, 불변의 비즈니스 규칙.. 인터넷이 아니더라도 현실에서 일어나는 사건들
