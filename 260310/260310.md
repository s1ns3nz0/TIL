# 4부. 목적 지향형 아키텍처로 가는 2가지 길
## 10장. 의도한 대로 모놀리스 구축
- 조직은 비즈니스 전략 목표를 충족하고 오랜 기간 동안 유지 관리 및 확장이 가능한 모놀리스를 설계, 구축하는 방법을 배워야 한다.
- 모놀리스를 만드는 왜(why?)와 어떻게(how)
    + 왜? 많은 소프트웨어 시스템이 마이크로서비스를 사용할 필요가 없다.
    + 어떻게? 빠른 반복, 점진적 가치 창출, 단계적 개선을 통한 실험이 가장 좋은 접근 방식이다.
- 모놀리스에는 3가지 주요 관심사와 목표가 있다.
    + 처음부터 모놀리스를 올바르게 설정하고 이를 유지하는 것
    + 이전에 잘못된 모놀리스를 바로 잡는 것
    + 모놀리스에서 마이크로서비스로 전환하는 것
- 컴포넌트 소스코드가 혼돈을 보이는 일반적인 방식은 다음과 같다.
    + 전략적 비즈니스가 아닌 기술에 초점
    + 체계적이지 않고 우연적인 구조(비아키텍처)
    + 비즈니스 중심의 모듈화 부족(기술적으로 동기가 부여된 최소한의 모듈만 존재)
    + 단위 테스트 없음(일부 크고 느린 계층 간 통합 테스트 수행)
    + 빈혈 모델(CRUD 애플리케이션)
    + 사용자 인터페이스와 여러 계층에 걸쳐 비즈니스 로직이 손실됨
    + 단일 기술 모듈 내에 많은 수의 프로그램 소스 파일 존재
    + 여러 컴포넌트 소스 파일(클래스)에 걸쳐 깊게 얽힌 커플링
    + 모듈 간 강력한 양방향 커플링
    + 컴포넌트 분리 없이 단일 컴포넌트가 여러 계층에 걸쳐 분리돼 있음
