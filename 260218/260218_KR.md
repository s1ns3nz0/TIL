# 1. Tag Policy와 AWS Cost 효율화
## 1) 기술 및 비즈니스에 맞는 태깅 전략 수립
### 기술 태그
- 이름: 개별 리소스 식별
- 애플리케이션 ID: 특정 애프릴케이션과 관련된 리소스 식별
- 애플리케이션 역할: 특정 리소스(웹 서버, 메시지 브로커, 데이터베이스)의 기능 설명
- 클러스터: 공통 구성을 공유하고 애플리케이션에 대해 특정 기능을 수행하는 리소스 팜 식별
- 환경: 개발, 테스트, 프로덕션 리소스 간 구별
- 버전: 리소스 또는 애플리케이션의 버전 구별
### 자동화용 태그
- 날짜/시간: 리소스를 시작, 중지, 삭제 또는 교체해야 하는 날짜 또는 시간 식별
- 옵트인/옵트아웃: 인스턴스 시작, 중지 또는 크기 조정과 같은 자동화 된 작업에 리소스를 포함할지 여부 지정
- 보안: VPC Flow 로그의 암호화 또는 활성화와 같은 요구 사항 결정, 추가 조사가 필요한 라우팅 테이블 또는 보안 그룹 식별
### 비즈니스 태그
- 프로젝트: 리소스가 지원하는 프로젝트 식별
- 소유자: 리소스에 대한 책임을 지는 사용자 식별
- 비용 센터/비즈니스 단위: 대개 비용 할당 및 추적을 위해 리소스와 연관된 비용 센터 또는 비즈니스 단위 식별
- 고객: 특정 리소스 그룹이 제공되는 특정 고객 식별
### 보안 태그
- 기밀성: 리소스가 지원하는 특정 데이터 기밀성 수준에 대한 식별자
- 규정 준수: 특정 규정 준수 요구 사항을 준수해야 하는 워크로드에 대한 식별자 
## 2) 비용 최적화를 위한 질문들
### AWS 공식 문서 상에서 제안하는 핵심 질문
원본링크: https://docs.aws.amazon.com/whitepapers/latest/tagging-best-practices/cost-allocation-tags.html
- 지출에 대한 소유권과 최적화 책임은 누구에게 있습니까?
- 어떤 워크로드, 애플리케이션 또는 제품에서 비용이 발생하고 있습니까? 어떤 환경 또는 단계에서 발생하고 있습니까?
- 어떤 지출 분야가 가장 빠르게 성장하고 있습니까?
- 과거 추세를 기반으로 AWS 예산에서 얼마나 많은 금액을 공제할 수 있습니까?
- 특정 워크로드, 애플리케이션 또는 제품 내에서 비용 최적화 노력의 영향은 무엇이었습니까?
